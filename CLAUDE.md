# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Cloudflare-first portfolio demo of **agentic RAG**: a single Worker serves both a Hono API and a
built React SPA, backed by Workers AI, Vectorize, D1, R2, KV, Workflows, and an Agents SDK Durable
Object. Epic #30 (the "agentic reimagine" — Agents SDK runtime, curated corpus, trace panel, eval
reporting, red-team mode) is **complete and merged to `main`**; current state and near-term work live
in `docs/status/now-next.md`.

`.github/copilot-instructions.md` describes the pre-#30 architecture as "pivot in progress" — that framing
is now stale (the pivot shipped), but its pointers to reusable infra (logger, trace, privacy, security
utils) are still accurate.

## Commands

```bash
npm run dev              # Worker dev server (wrangler dev, :8787) — bindings are mostly remote
npm run ui:dev            # Vite dev server (:3000), proxies /api/* to :8787 — run both together
npm run build              # corpus:build + ui build → outputs to ./public (served by the Worker)
npm run deploy              # build + apply remote D1 migrations + wrangler deploy

npm test                     # vitest (plain, not the Workers pool — see Testing below)
npx vitest run tests/utils/validation.test.ts   # single test file
npm run test:coverage
npm run test:e2e              # Playwright, against a running dev stack (see playwright.config.ts)

npm run lint                   # eslint . (root) + eslint in ui/ — CI lints these as two separate jobs
npm run typecheck                # tsc --noEmit on Worker code (root only; ui has its own tsc via build)
npm run format / format:check      # prettier; pre-commit hook (husky + lint-staged) runs this on staged files
npm run cf-typegen                  # regenerate worker-configuration.d.ts from wrangler.jsonc bindings

npm run db:create-migration <name>   # wrangler d1 migrations create wikipedia-db <name>
npm run db:migrate                    # apply locally
npm run db:migrate:remote               # apply to remote (required before deploying code that needs it)

npm run corpus:build                     # rebuild data/corpus/ + ui/src/content/corpus-manifest.json
npm run ingest:corpus [worker-url]        # POST the curated corpus to a running Worker
```

Node >=24.11.0 is required (CI pins Node 24; the lockfile needs npm 11 — `npm ci` on Node 20/22 fails
on optional `@cloudflare/workers-types` peers).

## Architecture

**Single-Worker deployment.** `wrangler.jsonc` configures `assets.directory: ./public` (SPA fallback) so
one `wrangler deploy` ships both the API and the built React app — no CORS, shared bindings. Locally this
means two dev servers: Wrangler on :8787 (Worker + all bindings) and Vite on :3000 (React + HMR), proxied
via `ui/vite.config.ts`. `public/` is generated by the UI build and stays untracked.

**Entry point:** `src/index.ts` — Hono app with all routes, plus the two exports Cloudflare needs to find
the Workflow and Durable Object classes: `export { IngestionWorkflow, RAGAgent }`. Route surface (all under
`/api/v1` except privacy and health):

- `GET/POST /api/v1/query` — legacy single-turn RAG comparison path (`src/patterns/basic-rag.ts`)
- `GET /api/v1/agent/bootstrap` + WebSocket at `/agents/ragagent/:session` — agentic path
- `POST /api/v1/ingest`, `GET /api/v1/ingest/:workflowId` — ingestion via Workflow
- `GET /api/v1/corpus/:id` — curated corpus browser
- `GET /api/v1/eval/report`, `POST /api/v1/eval/run` — demo-scale eval reporting
- `GET /api/v1/redteam/scenarios`, `POST /api/v1/redteam/try` — curated adversarial scenarios
- `GET/DELETE/POST /api/privacy/{export,delete,opt-out}` — session-ID-authed, short-TTL privacy endpoints
- `GET /health`, `GET /api/v1/docs`

**Two RAG paths coexist by design** (not redundant — the legacy path is a deliberate comparison point):

- `src/patterns/basic-rag.ts` — single-turn: embed → Vectorize query → fetch chunks from D1 → generate.
  Do not add new features here; it's frozen for comparison, not being extended.
- `src/agents/rag-agent.ts` (`RAGAgent`, extends `AIChatAgent`, SQLite-backed Durable Object) — the
  agentic path. Tool-calling loop (`retrieve_from_corpus` in `src/agents/rag-agent-tools.ts`) with every
  step pushed as a `TraceEvent` (`src/types/trace.ts`) into agent state, capped at `MAX_TRACE_EVENTS`.
  `validateStateChange` rejects any client-side mutation of `traceEvents`/`lastSources`/`traceId`/`spanId`
  — that state is server-owned; only the agent may write it.

**Storage split:** R2 (`ARTICLES_BUCKET`) holds full curated articles; D1 (`DATABASE`) holds chunk/document
metadata + FTS5; Vectorize (`VECTOR_INDEX`) holds embeddings (`@cf/baai/bge-base-en-v1.5`, 768-dim —
changing the embedding model requires recreating the index, see issue #20). KV embedding keys include
the model id (`emb:{model}:{hash}`). All of D1/Vectorize/R2 are `remote: true` in `wrangler.jsonc` —
there is no local Vectorize mode, so `npm run dev` talks to real remote resources even in dev.

**Generation model:** `@cf/meta/llama-4-scout-17b-16e-instruct` (function-calling capable, 131k context),
pinned in `src/config/models.ts` — change model IDs there, not inline at call sites. Agent retrieve
reranks with `@cf/baai/bge-reranker-base` (#21); do not add rerank to frozen `basic-rag.ts`.

**Trace propagation:** `src/utils/trace.ts` implements W3C traceparent (`traceId`/`spanId`). Both the
agentic trace panel and Workers logs read the same IDs — don't invent a second tracing scheme.

**Cross-cutting utils** (`src/utils/`): `logger.ts` (structured logging, child loggers, timers),
`chat-logger.ts` + `privacy.ts` + `privacy-data.ts` (chat logging with IP salting and the
export/delete/opt-out flows, session-ID authenticated with a short TTL), `security.ts` +
`rate-limiter.ts` + `validation.ts` (input validation, rate limiting).

**Eval and red-team are first-class demo surfaces**, not test-only tooling: `src/eval/` computes
faithfulness/groundedness/retrieval-relevance metrics against a small gold set (keep it labeled
demo-scale — never overclaim), surfaced at `/api/v1/eval/*` and `ui/src/pages/EvalPage.tsx`. `src/redteam/`
holds curated adversarial scenarios (prompt injection, out-of-corpus, hallucination pressure) with expected
defenses — deliberately not a freeform attack-tooling surface; scenario runs skip chat logging via the
ChatLogger gate (`tests/redteam/logging-gate.test.ts`).

## Testing

`npm test` runs plain Vitest (`vitest.config.ts` — `tests/**/*.test.ts`, no Workers pool despite
`@cloudflare/vitest-pool-workers` being a devDependency). These are unit tests against pure functions in
`src/utils/`, `src/ai/`, `src/eval/`, `src/redteam/` — no Miniflare bindings are simulated. `npm test` runs
in watch mode by default; CI and `npm run test:coverage` pass `--run`.

`npm run test:e2e` (Playwright, `e2e/*.spec.ts`) exercises eval and red-team pages against a live dev
stack — start `npm run dev` + `npm run ui:dev` first.

CI (`.github/workflows/`) runs two independent jobs: `root` (`eslint .`, `typecheck`, `npm test -- --run`)
and `ui` (`eslint . --max-warnings 0`, `npm run build`) — `npm run lint` at the root also lints `ui/`, but
that only works with `ui/node_modules` installed, which is why CI splits it.
